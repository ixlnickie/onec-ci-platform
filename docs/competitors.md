# Конкурентный анализ

| Аналог | Плюсы | Минусы | Отличие нашей среды | Источник |
| --- | --- | --- | --- | --- |
| Хранилище конфигурации 1С (встроенное) | родное, просто для небольших команд | нет автоматических проверок и сборки, нет MR-процесса | Git + MR + автоматический pipeline | https://its.1c.ru |
| Jenkins + OneScript/vanessa-runner | гибкость, большое сообщество 1С | необходимость самостоятельной настройки и поддержки Jenkins и инструментов автоматизации | pipeline как код рядом с кодом, MR-интеграция GitLab | https://github.com/vanessa-opensource/vanessa-runner |
| GitLab CI + gitsync | та же платформа GitLab, миграция из хранилища | нужно отдельно настраивать анализ кода и политики | готовый шаблон: Sonar + quality gate + правила веток | https://github.com/oscript-library/gitsync |
| TeamCity | зрелая CI-система | ограничения бесплатной редакции при масштабировании, интеграция с 1С требует настройки | локальная инфраструктура, ориентирована на 1С | https://www.jetbrains.com/teamcity/ |

Вывод:

Рассмотренные решения позволяют организовать совместную разработку и автоматизацию отдельных этапов работы с конфигурациями 1С. Однако для полноценного процесса CI/CD часто требуется дополнительная настройка и интеграция нескольких инструментов.

Разрабатываемая среда ориентирована на объединение хранения исходного кода, автоматизированных проверок и согласования изменений в едином процессе на базе GitLab. Её ключевое отличие — использование Merge Request для проверки изменений и CI/CD pipeline для автоматизации контроля качества кода.

Таким образом, цель разрабатываемой среды — упростить и объединить процессы разработки, проверки и согласования изменений в проектах 1С.
